{{ if not .Values.ingress.enabled }}
No Ingress. The workspace is reachable inside the cluster only, which is the
right default for a product whose whole premise is not being on the internet.
{{- end }}

Two things worth knowing before you scale this:

* The probes use /health, not /ready. /ready reports 503 when the model plane is
  unreachable, and as a readiness probe that empties the Service the moment a
  *shared* dependency fails — turning a partial outage everyone can see into a
  total one nobody can diagnose. Alert on /ready; do not probe with it.

{{ if not .Values.scheduler.separate }}
* This pod runs the scheduler in-process, so `replicaCount` above 1 would
  generate every brief once per replica. The chart refuses that combination with
  SQLite; on PostgreSQL, set scheduler.separate=true first.
{{- else }}
* The scheduler Deployment is pinned to one replica and uses the Recreate
  strategy, because a rolling update would briefly run two of them.
{{- end }}
